# Suno 批量下载助手（侧边栏版 v0.2.1）

**0.2.1 外观更新：** 为 2K 屏幕提高侧栏文字、按钮、列表及状态信息的字号，保持紧凑布局；新增原创蓝青色音符图标（16/32/48/128 PNG），用于工具栏、扩展管理界面及侧栏标题。识别、入队和下载逻辑未改动。

一个供用户整理并下载自己拥有权利的 Suno 歌曲的 Chrome/Edge **Manifest V3** 扩展。点击工具栏图标，在浏览器侧边栏进行“识别 → 勾选 → 入队 → 下载”，无需打开独立的管理标签页。

## 安装

1. 下载仓库中的代码并解压到固定目录（目录根部应包含 `manifest.json`）。
2. 在 Chrome 打开 `chrome://extensions`，Edge 打开 `edge://extensions`，启用开发者模式。
3. 选择“加载已解压的扩展程序”，选择该目录。
4. 打开 Suno 歌曲或曲库页，点击工具栏中的扩展图标打开侧边栏。

最低 Chrome 版本为 116；Edge 需要支持 Chromium `sidePanel` API 的版本。侧边栏位于左侧还是右侧取决于浏览器的侧边栏位置设置。

## 使用

- **识别链接**：每行输入一个歌曲 ID、歌曲链接、短分享链接或公开歌单链接。长输入列表按顺序解析，不限制本地歌曲数目。
- **收集当前页面**：提取当前 Suno 页面 DOM 中已有的 `/song/` 或 `/s/` 链接，并尽量读取其显示标题。页面未渲染的歌曲需滚动加载后再收集；不会抓取账号 Cookie、令牌或私密曲库 API。
- **选择并加入队列**：识别后可逐首勾选、全选、取消全选；不会自动下载。已在下载队列中的歌曲会跳过。若第三方歌名不准确，可以在识别清单里点击“改名”，保存后再入队；排队中或失败的歌曲也会同步新名称。
- **下载**：默认两首并行，可选 1–3；文件存放在浏览器下载目录的 `SunoBatch/` 子目录，名字只使用识别到的标题（不拼接 ID）；同名文件由浏览器自动编号。
- **恢复**：扩展本地存储保存识别结果与下载队列；再次打开会查询浏览器的下载记录恢复状态，默认暂停派发新任务。

## 关键限制

此工具**依赖** `https://download.ai-suno.com` 提供歌曲数据和临时媒体 URL，无法自行解决服务失效、歌单返回前 50 首、私人歌曲解析失败或下载限速等服务端限制。**本地识别和队列不设 50 首的限制**；可以导入 100、200 条或更多链接分批处理，但某一个歌单 API 只返回 50 首时，请从 Suno 页面滚动分次收集或粘贴剩余歌曲链接。不要将这理解为已绕过服务端上限。

从 Suno 页收集时优先使用 DOM 中读取的歌名；只提供链接时则依赖第三方 API 返回标题，如果 API 提供通用标题（例如 `track_10`），扩展无法保证等于 Suno 页面显示标题。

仅保存接口提供的原媒体文件并以 `.m4a` 命名，不进行 MP3/WAV 转码，也未逐文件检验真实音频编码。浏览器状态 `complete` 表示下载传输结束，不代表音频已通过播放验证。

队列派发由侧边栏页面维持。关闭侧边栏后已交给浏览器的下载通常会继续，但尚未派发的任务会暂停；重新打开后可手动继续。解析→浏览器接单→本地保存编号之间存在极小的中断窗口，无法保证绝对的跨崩溃恰好一次派发。

## 隐私与安全

无需 Suno 密码、Cookie 或会话令牌。代码请求第三方服务时明确使用 `credentials:'omit'`，只会把用户输入的歌曲/歌单链接发送给解析服务。获取的临时媒体 URL 交给浏览器下载管理器。识别结果、歌曲 ID、标题、下载编号和状态存储于 `chrome.storage.local`。不得提交私人音频、令牌、Cookie 或 HAR 网络抓包文件。界面、排版与标识均为独立实现，不复用第三方插件的设计资产。

本仓库包含零依赖 Node.js 测试：`npm test`。可检查输入限制、文件名规则、状态机基本转换、延迟重试和 MV3/CSP 静态配置。
